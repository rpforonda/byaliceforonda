# catchupwithalice.com

Official site for children's book author **Alice Foronda** (`byaliceforonda`) — a small,
fully static marketing site built with SvelteKit and deployed to GitHub Pages at
[catchupwithalice.com](https://catchupwithalice.com).

There is no backend: no server code, no database, no API, no runtime request handling. Every
route gets its own HTML file at build time, and everything else (page content, menus,
animations, the newsletter popup) is rendered in the browser. Purchases, newsletter sign-ups and
Hoksi Haus banner requests happen on third-party services (Amazon, MailerLite, Google Forms), so
the site itself collects no personal data. `/privacy` explains each of them to visitors.

> Looking for the visual language — colors, type, components, motion? See
> [`docs/DESIGN.md`](docs/DESIGN.md).

## Stack

| Concern        | Choice                                                            |
| -------------- | ----------------------------------------------------------------- |
| Framework      | [SvelteKit 3](https://svelte.dev/docs/kit) with **Svelte 5 runes** |
| Rendering      | `@sveltejs/adapter-static` — every route prerendered to full HTML at build time, then hydrated |
| Styling        | [Tailwind CSS v4](https://tailwindcss.com) via `@tailwindcss/vite`|
| Images         | [`@sveltejs/enhanced-img`](https://svelte.dev/docs/kit/images) — AVIF/WebP + `srcset` at build time |
| Build          | [Vite 8](https://vite.dev)                                        |
| Hosting        | GitHub Pages (custom domain via `static/CNAME`)                   |
| CI/CD          | GitHub Actions (`.github/workflows/deploy.yml`)                   |

`+layout.js` sets `prerender = true`, `ssr = true`, `csr = true`: each page is rendered to
complete HTML at build time (content, headings, images, `<title>`, meta tags), then hydrated
in the browser. There's still no server — `ssr` only means "render at build time" here. Keep
browser-only code (`window`, `document`, `localStorage`) inside `onMount` / `$effect` /
event handlers, or the build will fail.

SvelteKit 3 has no `svelte.config.js`: the SvelteKit options (adapter, `paths`, `prerender`,
compiler options) are passed to the `sveltekit()` plugin in `vite.config.ts`. Imports from
`src/lib` use the `#lib/...` subpath import defined in `package.json` (SvelteKit 3 removed
`$lib`).

## Getting started

```bash
npm install
npm run dev        # local dev server (Vite)
npm run build      # static build → build/
npm run preview    # serve the production build locally
```

The adapter writes an SPA fallback to `build/404.html`, so GitHub Pages serves it for unknown
paths and the client router takes over.

Requires **Node 22.17 or newer** (SvelteKit 3's minimum); CI builds with Node 26.

The Cosmic Dash game engine is written in Rust, so `dev` and `build` first run `npm run wasm`,
which needs:

```bash
rustup target add wasm32-unknown-unknown   # Arch without rustup: pacman -S rust-wasm
cargo install wasm-bindgen-cli --version 0.2.129 --locked
```

`~/.cargo/bin` must be on your `PATH`, and the CLI version must equal the `wasm-bindgen` version
pinned in `cosmic-dash/Cargo.toml` (bump both together).

If your system has libvips installed (e.g. Arch Linux), `sharp` (used by enhanced-img) tries
to compile against it and `npm install` fails with *"Please add node-addon-api to your
dependencies"*. Use its prebuilt binary instead:

```bash
SHARP_IGNORE_GLOBAL_LIBVIPS=1 npm ci
```

## Project structure

```
vite.config.ts          # Vite plugins + SvelteKit options (adapter-static, paths, prerender)
cosmic-dash/            # Rust crate: the Cosmic Dash game engine, compiled to WebAssembly
  src/lib.rs            # characters, game state, simulation, and the `Game` API the component calls
  src/draw.rs           # all canvas drawing, including the intro / character-select screen
  pkg/                  # generated by `npm run wasm` (gitignored), imported as `#cosmic-dash`
src/
  app.html              # document shell; injects SvelteKit head/body (fonts load via +layout)
  app.css               # Tailwind import + base layer (focus styles, motion, .page-shell)
  lib/
    CosmicDash.svelte   # "Crosby's Cosmic Dash" — UI shell around the Rust game engine
    Seo.svelte          # per-page <head>: title, description, canonical, Open Graph, JSON-LD
    PageBackdrop.svelte # a photo pinned behind a page (/about, /book) while the content scrolls over it
    seo.js              # site URL, share image, author + book structured data
    hoksi/              # Hoksi Haus: sizes, prices, form link (data.js), gallery list (gallery.js), MailLink
    assets/             # all images the pages use (processed at build time)
      game/             # Cosmic Dash character sprites
      hoksi/            # Hoksi Haus logo; gallery/ holds the banner photos
  routes/
    +layout.svelte      # header, nav, footer, mobile menu, View Transitions
    +layout.js          # prerender / csr / ssr flags
    +page.svelte        # home: hero, book promo, newsletter popup, characters
    about/+page.svelte  # author bio: the hello letter over a pinned photo of Alice
    book/+page.svelte   # book info + buy button → Amazon, over the pinned night-sky illustration
    freebies/+page.svelte  # promoted Cosmic Dash card + coloring-page PDFs
    freebies/cosmic-dash/+page.svelte  # the Cosmic Dash game page
    hoksi-haus/+page.svelte  # Hoksi Haus banner studio: gallery, sizes & prices, how to order
    privacy/+page.svelte     # privacy notice (linked from the footer)
    shop/+page.svelte   # "coming soon" placeholder (not in nav, noindex)
    sitemap.xml/+server.js  # prerendered sitemap of the public pages
static/                 # served as-is: coloring-page PDFs, favicons, og-image.jpg, robots.txt, CNAME, .nojekyll
.github/workflows/deploy.yml
```

Nav exposes **home / about / book / freebies / hoksi haus**. The game page, `/freebies/cosmic-dash`, is
reached from the card on `/freebies` and links back to it. `/privacy` is linked from the footer.
`/shop` exists but is an unlinked placeholder.

**Stacked sections:** on any page with more than one top-level `<section>` (home, hoksi haus),
each section is a full-width sheet.
- Each sheet is at least a screen tall and sticks under the header (`position: sticky`) while
  the next one slides up over it. Nothing animates. The rules live at the end of `app.css`.
- A small script in `+layout.svelte` measures any section taller than the screen and makes it
  stick higher by the difference, so it scrolls fully into view first.
- The last section doesn't stick, so the footer follows it normally. Single-section pages
  (freebies, the game, privacy, shop, about, book) are left as they are.
- `<main>` uses `overflow-x: clip`, because `hidden` would make the sections stick inside
  `<main>` instead of the page.
- To take part, a section must sit directly in `<main>`, span the full width (put `page-shell`
  on a child, not the section), and keep its own `style` attribute free, since the script sets
  `--overflow` there.

**Page backdrops:** `/about` and `/book` show their photo as a pinned background
(`PageBackdrop.svelte`). The photo fills the screen below the header and stays put while the
page's single content section scrolls over it.
- The section is `relative`, so it paints above the fixed photo.
- The section has `.over-backdrop` (app.css), which starts it 80% of the way down the first
  screen, so the photo shows on arrival.
- `/about` passes `natural`, because its photo is only 1086×724 and looks grainy stretched to
  fill the screen. It's shown at its own size at most, as a framed print centered below the
  header. On phones it's too small to pin, so it sits in the page above the letter instead.
  Swap in a larger original when there is one.

## Content & integrations

- **Characters:** Carla, Crosby, and Tank — featured on the home page.
- **Book purchases:** `src/lib/BuyButtons.svelte` (used on `/book` and the home page) shows a
  single "buy on amazon · paperback" button (`amazon.com/dp/B0HFTDNCKW`) opening in a new tab.
  The URL lives in `src/lib/seo.js` as `AMAZON_URL`; the book's JSON-LD lists the Amazon listing
  as its paperback edition (`workExample`). (The Shopify store is closed, so Amazon is the sole
  retailer.)
- **Newsletter:** "Join Crosby's Crew" — a MailerLite embedded form shown in a popup
  modal on the home page (`assets.mailerlite.com`, form id `QQryIS`).
- **Freebies:** `/freebies` leads with a promoted card for **Crosby's Cosmic Dash**, a browser
  game at `/freebies/cosmic-dash` (see below), followed by three printable coloring-page PDFs
  (Crosby, Tank, Carla) served from `static/` and linked with `asset()`.
- **Hoksi Haus:** `/hoksi-haus` is the page for Hoksi Haus, a hand-painted party-banner studio.
  - Sizes, prices, add-ons, turnaround, the order form link and the contact address live in
    `src/lib/hoksi/data.js`. Keep them in step with the Google Form's options.
  - Orders go through a Google Form that's **linked, not embedded**, so a visitor's browser only
    contacts Google if they open it.
  - To add a gallery photo, put it in `src/lib/assets/hoksi/gallery/` (about 1600px on the long
    side) and list it in `src/lib/hoksi/gallery.js` with a title and alt text. A listed photo
    with no matching file fails the build. Until the first photo is listed, the page shows a
    "coming soon" note.
  - The gallery ("recent work") is an endless filmstrip carousel. The photos sit side by side
    at one height, each at its own width, and drift slowly to the left (30 px/s), looping
    forever.
    - It loops by rendering the photos three times in a row. The strip jumps by one set's width
      whenever it passes the middle set, landing on identical photos.
    - It pauses while the mouse is over it, while a photo has keyboard focus or is open full
      size, for 3 s after a touch or after closing a photo, and with its pause button.
      Visitors who ask for reduced motion start paused.
    - It's still a native scroll strip, so swiping and the arrow buttons work too. The arrows
      jump a screenful without animating.
  - Tapping a photo opens it full size in a popover, with no JavaScript. The full-size image is
    lazy, so it only downloads when opened.
  - Strip location data from photos before adding them (phone photos carry GPS). For example,
    `magick in.heic -auto-orient -resize '1600x1600>' +profile '!icc,*' out.jpg` keeps only the
    color profile.
  - In `npm run dev`, enhanced-img encodes each image size on request (about 5 s for a large
    AVIF), so judge gallery speed with `npm run build && npm run preview`.
  - The contact address is stored in two parts and only put together in the browser
    (`src/lib/hoksi/MailLink.svelte`), so it never appears whole in the repo or the HTML.
- **Social:** Instagram `@byaliceforonda`, TikTok `@catchupwithalice` (footer).

### Crosby's Cosmic Dash

A self-contained `<canvas>` endless-runner (Chrome-dino style) on its own page,
`/freebies/cosmic-dash`, built from a Rust engine (`cosmic-dash/`) and a Svelte shell
(`src/lib/CosmicDash.svelte`). The `/freebies` page links to it with a promoted card (a
night-sky panel with the three sprites and a "play now" button) above the coloring pages.

Everything about the game happens inside the canvas. The intro screen is the character
select: three friend cards (sprite, name, 5-star power rating), the chosen friend's role,
passive and special move, and the controls. Pick a character (Crosby, Carla, or Tank), run
across a moon surface in deep space, jump moon rocks and space crystals, duck (or jump)
shooting comets, and collect stars. The nebula colors change every 500 points (Purple Nebula →
Teal Galaxy → Rosy Starfield → Golden Comet Belt).

- **Characters & skills:** each friend has a passive perk and a special move charged by
  collecting stars. Crosby, the main hero, is deliberately the strongest.

  | Character | Passive | Special (stars to charge) |
  | --------- | ------- | ------------------------- |
  | Crosby | Starlight Double Jump — jump again mid-air | Brave Heart (6) — 5s invincible: smash obstacles, star magnet, double score |
  | Carla | Navigator's Map — off-screen obstacle warnings + star magnet | Calm Compass (9) — slows the world for 4s |
  | Tank | Spring Gadget — higher held jump | Rocket Pack (9) — fly safely over everything for 3s |

- **Sprites:** colored versions of the pencil character sketches, painted in the book-cover
  palette, in `src/lib/assets/game/` (imported, so Vite fingerprints them).
- **Controls:** on the intro, ← / → (or A / D) choose a friend and Space starts. In a run:
  Space / ↑ / W to jump (hold for a higher jump), ↓ / S to duck, X / E / Shift for the special
  move, P / Esc to pause. After a crash, Space retries and ← / → (or the "choose a friend"
  button) go back to the intro. On touch: tap a friend card to choose and tap again (or
  anywhere else) to start, tap to jump, swipe down to duck, and the ★ button under the canvas
  for the special. On-screen hints switch between keyboard and touch wording based on the last
  input.
- **Tech:** the engine is Rust compiled to WebAssembly with `wasm-bindgen`/`web-sys`. It owns
  the simulation (physics, spawning, collisions, specials, scoring) and draws every frame with
  Canvas 2D, including the intro / character select and the crash screen. Taps are hit-tested
  in the engine (`Game::tap`). The Svelte component owns sprites, keyboard/touch input, the `requestAnimationFrame` loop, `localStorage`,
  aria announcements, and score sharing, and drives the engine through `Game` methods
  (`press_jump`, `use_special`, `frame`, …). The wasm (~50 KB gzipped) is loaded with a dynamic
  `import("#cosmic-dash")` in `onMount`, so only the game page downloads it and prerendering
  never runs it. If it fails to load, the game area shows a message and a reload button. DPR-aware sizing via `ResizeObserver`; auto-pauses on tab-hide
  (`visibilitychange`) and on blur.
- **Tuning:** physics and spawn constants, and the `CHARACTERS` table (stats, hitboxes,
  accents, and the role/passive/special text shown on the intro), are at the top of
  `cosmic-dash/src/lib.rs`. The component reads the chosen character back with
  `game.character()`.
- **Persistence:** high score only, in `localStorage` (`catchupwithalice-cosmic-dash-hi`),
  guarded by try/catch. No network, no personal data.
- **Share score:** the game-over screen offers a "share my score" button that generates a
  1080×1080 score-card **image** (drawn off-screen on a canvas) and shares it plus a caption via
  the Web Share API — so it posts properly to Instagram/Facebook, which ignore pre-filled text.
  Fallbacks: text-only share, or (desktop) saving the card image to post manually. The card and
  text are built entirely in the browser from the run's numbers (score, character, game, site
  URL) — no name, identifier, or server call, and the canvas stays untainted (same-origin
  sprites), so it collects nothing.
- **Accessibility:** `role="application"` with a visually hidden description of the controls,
  keyboard-operable (including character select), the chosen friend's role and moves as text
  (shown below the game on narrow screens, visually hidden otherwise), an `aria-live` region
  that reads out each new choice, special moves and game-over, and a visible focus outline.

## Images

Every image a page shows lives in `src/lib/assets/` and is rendered with `<enhanced:img>`,
which generates AVIF + WebP (plus a PNG/JPEG fallback) at build time and adds `width`/`height`
to prevent layout shift:

```svelte
<enhanced:img src="#lib/assets/cosmic.jpeg" alt="…" width="1280" class="…" />
```

Pick the sizing that matches how the image is displayed:

- **Source is at least 2× its displayed size:** set `width` to 2× the largest CSS width (e.g.
  `width="160"` for an 80px logo). You get a 1× and a 2× version.
- **Image spans the layout responsively:** set `sizes` (e.g.
  `sizes="(min-width: 1280px) 1100px, 100vw"`). You get a range of widths for the browser to
  choose from.
- **Source is smaller than 2× its display size:** use one width at the source size:
  `src="#lib/assets/joincrosby.png?w=463"` **and** `sizes="463px"`. Without `sizes`, the
  browser assumes `100vw` and the image renders larger than intended.

Mark the largest above-the-fold image `fetchpriority="high"` and leave out `loading="lazy"`
on anything visible without scrolling. Assets used from script (like the game sprites) are
imported normally (`import sprite from "#lib/assets/game/crosby.webp"`) so Vite fingerprints
them and a missing file fails the build.

`<enhanced:img>` wraps each `<img>` in a `<picture>`. `app.css` sets `picture { display:
contents }` and hides its `<source>` children so layouts behave as if the `<img>` were
unwrapped.

Only put files in `static/` when they need a stable, unhashed URL (PDFs, favicons, CNAME).
GitHub Pages can't redirect, so renaming or removing anything there breaks existing links.

## Modern CSS and fallbacks

The site uses a few newer CSS features (`progress()` and `text-box` are Baseline 2026). Each
has a fallback, so older browsers keep the previous look:

- **`progress()` for fluid sizes.** The `fluid-text-*` classes in `app.css` grow text smoothly
  from a 375px phone to the 1100px page width, instead of jumping at a breakpoint.
  - Each class is named after the Tailwind sizes it replaces, and sits next to them on the
    element (`fluid-text-4xl-5xl text-4xl md:text-5xl`). Browsers without `progress()` drop the
    declaration and use those classes.
  - Spacing that used `clamp()` with viewport units declares the `clamp()` first and a
    `progress()` line after it that gives the same result between explicit screen widths.
  - Don't combine `progress()` and `var()` in one declaration. An older browser would accept it
    because of the `var()`, let it override the fallback, and then fail to compute it. Put
    those behind `@supports` instead (see the Hoksi Haus carousel photo height).
- **`text-box` trimming.** `.trim-text` trims a box's text to its cap height and baseline, so
  it sits optically centered in buttons, pills and badges. It adds the trimmed
  `(1lh - 1cap) / 2` back as vertical padding, so the element keeps its size.
  - Set `--pad-y` to the element's own vertical padding, since this padding replaces it
    (e.g. `py-2 [--pad-y:0.5rem]`).
  - Use it on block containers: an inline-block button, or a `<span>` inside a flex button.
    Text that's a loose part of a flex container isn't trimmed.
  - It's inside `@supports (text-box: …)`, so older browsers keep the untrimmed text and
    padding.
- **`lh` units.** Spacing tied to the text is written in `lh`, with an `em` or `rem` value
  declared first for older browsers. Examples are the letter's one-line gap between paragraphs
  and the privacy page's paragraph and list spacing.

The minifier keeps both declarations of each pair; check the built CSS if you change this.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy.yml`, which installs the Rust wasm
target and `wasm-bindgen`, runs `npm ci && npm run build`, uploads `build/` as a Pages artifact, and deploys it. The workflow uses the official
GitHub Pages OIDC flow; the `pages: write` / `id-token: write` permissions are scoped to the
deploy job.

Pull requests into `main` run the same build **without deploying** (the build job checks the
PR merged with the current `main`), so a broken build shows up on the PR instead of in
production.

### GitHub Pages constraints

Because the host serves static files only, keep these in mind:

- **No custom HTTP headers** — no `Cache-Control`, no CSP or redirects at the server. Use
  `<meta>` / `<link rel="preload">` in `app.html` instead, and hashed filenames for cache-busting.
- **Custom domain** — `static/CNAME` (`catchupwithalice.com`) and `static/.nojekyll` must stay
  in `static/`. Leave `BASE_PATH` empty (custom domain serves from root).
- **Routing** — `/about` is served from `about.html`; unknown paths fall through to `404.html`.

### SEO

- Every page renders a `<Seo>` component (`src/lib/Seo.svelte`) with its own title,
  description and canonical URL, plus Open Graph / Twitter tags pointing at
  `static/og-image.jpg` (1200×630, from the book's starry-night spread). Change site-wide
  values (URL, share image, author/book details) in `src/lib/seo.js`.
- Structured data (JSON-LD): `WebSite` + `Person` + `Book` (with ISBN) on the home page, `Book` on `/book`,
  `ProfilePage` on `/about`.
- `/book` keeps its description in artwork, so the image has a screen-reader-only transcript
  (linked with `aria-describedby`) that crawlers can read. Update the transcript if the
  artwork changes.
- `/about`'s hello letter is real text in `src/routes/about/+page.svelte`, styled to look like
  the original artwork: Lora on cream paper, with "Hello." and the signature in Ms Madi. Both
  fonts are self-hosted and load only on that page. Edit the wording there directly.
- `sitemap.xml` is generated at build time and referenced from `static/robots.txt`. Add new
  public pages to the list in `src/routes/sitemap.xml/+server.js`.
- `/shop` is `noindex` until it has real content.

## Security & privacy

This is a static site with a narrow attack surface. No user input reaches the DOM (no forms,
no `fetch`, no reading of URL params), no `{@html}`, and all external links carry
`rel="noopener noreferrer"`. The only embedded third party is the MailerLite signup iframe,
whose `src` is hardcoded. No analytics or trackers are bundled, and **fonts are self-hosted**
(`@fontsource`, bundled at build) rather than fetched from Google — so apart from the home
page's MailerLite popup, no visitor data leaves for a third party and the site stays
cookieless. The Hoksi Haus order form is a link to Google Forms, not an embed. `/privacy`
describes every data flow (GitHub Pages' IP logging, the game's best score in `localStorage`,
the newsletter popup, the order form); update it whenever one changes. The sole hardening gap
is the absence of a Content-Security-Policy `<meta>` tag (GitHub Pages can't set CSP headers).
